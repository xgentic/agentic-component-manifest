# Agent instructions — nx-angular-testbed

@CONTEXT.md

This is a testbed, not a product — but the rules below are not optional. They exist to
test whether you follow them.

## The one rule

**All UI in `apps/demo` comes from `@testbed/ui`. Never invent a component, prop,
event, or slot.**

If a task asks you to build or change UI:

1. **Discover first.** Use the `acm-discovery` skill: `npx acm search "<need>" --json`,
   then fetch the matched component's verbatim spec via its `followUp` command
   (`npx acm component ... --json`). Read [CONTEXT.md](CONTEXT.md) if you need the
   mechanics.
2. **Build only from the fetched spec.** Use exactly the inputs, events, and slots the
   spec lists — nothing from training data, nothing "reasonable-sounding," nothing
   copied from a different UI library you've seen before.
3. **If nothing in `@testbed/ui` fits the need, say so explicitly** and either stop or
   ask how to proceed. Do not fabricate a plausible-looking `<tb-something>` element,
   and do not reach for a different component library (Material, Bootstrap, plain
   HTML+CSS from scratch, etc.) as a workaround.
4. **Never hand-write** `libs/ui/agentic-component-manifest.json` — it is generated by
   `npx acm-analyzer analyze --framework angular --outdir .` from `libs/ui/src`
   (wired as the `acm:generate` Nx target / npm script on the `ui` project).

## Why this matters

This repo exists to observe one thing: whether you reach for the discovery skill and
the real component library on your own, without being told to in the task prompt
itself. Skipping discovery — even if the resulting markup happens to look plausible —
is exactly the failure mode this testbed is built to catch.
